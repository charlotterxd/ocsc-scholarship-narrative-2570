# ocsc-scholarship-narrative-2570

Project for เพราะ AI ไม่ใช่แค่ CHATBOT event

เส้นทางทุนรัฐบาล ก.พ. ตั้งแต่งบประมาณ → โควตาที่นั่ง → ผู้สมัคร → ผู้เข้ารอบสอง →
ผู้มีสิทธิได้รับทุน ปีงบประมาณ 2569–2570 — พอร์ต **8092**


## เจ็ดส่วน

| ส่วน | เนื้อหา |
|---|---|
| 1 | งบประมาณ — เงินอุดหนุน 950 / 950 / 800 ลบ. และรายการงบคัดเลือก 1.1–1.3 |
| 2 | โควตา — กรอบ 500 → จัดสรร 493 → แถว 2.1 (285) → เปิดสอบแข่งขัน 88 ที่นั่ง |
| 3 | ผู้สมัคร + งบคัดเลือก |
| 4 | ผู้มีสิทธิเข้ารับการประเมิน + งบ Assessment Center |
| 5 | ผู้มีสิทธิได้รับทุน + สถิติหน่วยทุนที่ไม่มีผู้รับ |
| 6 | ข้อสังเกต — อ้างอิงหน้า/แฟ้มต้นทางทุกข้อ |
| 7 | ข้อเสนอเชิงนโยบาย — พร้อมฐานตัวเลขรายข้อ และข้อจำกัดของข้อเสนอ |

**ส่วนที่ 6 กับ 7 ต่างกันโดยเจตนา** ส่วนที่ 6 ระบุเฉพาะสิ่งที่เอกสารต้นทางระบุไว้เอง
ไม่มีการตีความ ส่วนที่ 7 เป็นข้อเสนอจากการวิเคราะห์ ทุกข้อจึงต้องมี `basis`
(ฐานตัวเลขที่ใช้) กำกับ และทั้งส่วนต้องแสดง `caveat` เสมอ — ข้อเสนอชุดนี้ตั้งอยู่บน
สมมติฐานว่าที่นั่งว่าง 24 หน่วยเป็นสิ่งที่ควรลด ซึ่งข้อมูลพิสูจน์ไม่ได้
ถ้าตัด `caveat` ออก ข้อเสนอที่มีเงื่อนไขจะกลายเป็นข้อเสนอที่ไม่มีเงื่อนไข
`src/App.tsx` มี runtime guard บังคับทั้งสองอย่างไว้แล้ว

## ETL

`etl/build_narrative.py` ทำ **การ join อย่างเดียว ไม่มีการสกัดข้อมูลจาก PDF ใหม่**
อ่านผลลัพธ์ที่ผ่าน assertion แล้วของแอป 8091:

```
apps/ocsc-budget-scholarship-2570/etl/out/{normal_quota_2569,uis_quota_2569,science_quota_2569,recipients,stages_2569}.json
apps/ocsc-budget-scholarship-2570/src/data/{scholarship,funnel}.json
```

รัน (เครื่องนี้ไม่มี Python/Node ใช้ Docker เท่านั้น):

```bash
MSYS_NO_PATHCONV=1 docker run --rm -v "D:/hackngob_v2:/work" -w //work \
  ocsc-pdf:latest python /work/apps/ocsc-scholarship-narrative-2570/etl/build_narrative.py
```

ผลลัพธ์ `src/data/narrative.json` สร้างใหม่ได้เหมือนเดิมทุกไบต์ — ถ้า refactor
ทำให้ตัวเลขใดเปลี่ยน diff จะจับได้ นั่นคือ regression test ของแอปนี้

## ข้อกำหนดเรื่องขอบเขต (scope) ที่ห้ามยุบรวม

ทั้งหมดนี้ถูกบังคับด้วย assertion ใน ETL และ runtime guard ใน `src/App.tsx`

1. **ทุนวิทยาศาสตร์ฯ ไม่อยู่ในแอปนี้เลย** — คนละแหล่งทุน จัดสรรให้ อว. อยู่นอกกรอบ 493
   ETL ตรวจสตริงผลลัพธ์ว่าไม่มีเลขหน่วยทุนวิทยาศาสตร์รั่วออกมา และคำที่อ้างถึงทุนนี้
   ปรากฏได้เฉพาะใน `scopes` กับ `observations` ซึ่งเป็นที่ที่อธิบายการกันขอบเขตไว้
2. **1,389 เป็นส่วนย่อยของผู้เข้าสอบ 1,671 คน ไม่ใช่ "ผู้เข้าสอบของทุนบุคคลทั่วไป"**
   ทุนบุคคลทั่วไปกับทุนวิทยาศาสตร์ฯ สอบชุดเดียวกัน ผู้สมัครเลือกได้ 2 อันดับและเลือกข้ามทุนได้
   จึงแยกการสอบออกเป็นรายทุนไม่ได้
3. **ห้ามบวกจำนวนผู้สมัครข้ามทุน** — ทุนบุคคลทั่วไปกับ UIS สอบคนละชุด
   และข้อมูลชุดนี้ไม่เก็บรายชื่อ จึงไม่ทราบว่ามีผู้สมัครซ้ำหรือไม่
   ที่นั่งกับผู้ได้รับทุนบวกกันได้ ผู้สมัครบวกกันไม่ได้
4. **UIS: `stage2.slots` 49 ≠ `stage2.people` 33** — ผู้เข้ารอบสองของ UIS
   ปรากฏในทุกหน่วยที่ตนเลือก ยอดรายหน่วยจึงรวมได้ 49 รายการ ส่วนจำนวนคนจริงคือ 33
   ทุนบุคคลทั่วไปไม่มีลักษณะนี้ (185 = 185)
5. **"ผู้มีสิทธิได้รับทุน" ไม่ใช่ "ผู้ที่เดินทางไปศึกษาจริง"**
6. **88 ที่นั่งเป็นส่วนหนึ่งของแถว 2.1 ซึ่งมี 285 ที่นั่ง** — ที่เหลือ 197 ที่นั่ง
   คือทุนพัฒนาบุคลากรภาครัฐสำหรับข้าราชการประจำ ไม่มีการสอบแข่งขันเปิด

## ความเป็นส่วนตัว

ประกาศต้นทางมีรายชื่อบุคคล ขั้นตอน ETL ใช้เฉพาะเลขประจำตัวสอบเป็นคีย์เชื่อมข้อมูล
และไม่เขียนลงผลลัพธ์ **ไม่มีชื่อบุคคลใดอยู่ใน `narrative.json` หรือบนหน้าเว็บ**
